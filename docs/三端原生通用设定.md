## 架构核心设定

### UDP广播发现接口

执行多播检测局域网接口，对全部局域网广播地址启动 UDP/7431 广播

发送固定心跳包
```json
{
  Device_ID: "string",  // 固定随机生成的ID唯一值
  Device_OS: "string",  // 设备操作系统
  Device_Name: "string",  // 用户可设定的设备名称
  TCP_Port: "int",  // TCP数据接收、发送端口
  Timestamp: "int64"  // 最后活跃时间戳
}
```

实现`StartBroadcast()` （发送心跳包）和`StartListener()`（监听和解析设备），通过时间戳判断在线状态（10秒超时）

### TCP传输

实现TCP文件传输，`TCPServer`（接受文件）与`TCPClient`（发送文件）

- 支持 1MB 分片传输，记录已传偏移量实现断点续传
- 支持大文件传输优化
- 实现通过系统权限与系统原生API直接获取文件传输，避免产生文件副本占用存储

### 设备管理

在线设备列表维护/排序：
用`map`存储设备信息，按“最近活跃时间”排序，提供`GetonlineDevices()`接口

**特殊兼容性设计**：当同网段内两个设备ID广播是发现ID相同，两者通过广播UDP协议协商各具`1/2`可能性变更本局域网内不存在的其他ID

## 统一UI设计

### 主页

根据后端 UDP广播 `StartBroadcast()` 监听列出在线设备列表

- 对不同端设备UI做优化（Linux、Windows、HarmonyOS、Android）

选中设备以后，启动选择文件区域，允许用户选择系统文件，允许选择多个文件
选择完成后启动“上传到XXX(`Device_Name`)”按钮，点击后启动上传任务

设计传输任务队列，实时监听显示本设备上正在进行的传输任务

- 显示对端设备信息（`Device_Name` `Device_OS` `Device_IP`）
- 显示传输状态、进度

### 配置

设计配置修改UI，允许用户修改的软件参数：
设备名称`Device_Name`、TCP端口`TCP_Port`

**所有配置需要实现即时修改后端即时变更**
