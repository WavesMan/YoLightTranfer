# 文件传输协议改进总结

## 问题分析

### 原始问题
1. **ACK确认超时**：发送端等待接收端的FILE_END确认时超时
2. **文件接收失败**：接收端接收的文件大小为0字节
3. **二进制数据处理不当**：接收端无法正确处理二进制数据流

### 根本原因
- 缺少**传输计划协商阶段**，导致双方对数据量的期望不一致
- 二进制数据接收机制不完善，容易丢失数据
- 没有明确的分片信息，接收端无法验证接收的完整性

## 解决方案

### 1. 新增传输协议定义文件
**文件**: `lib/util/transfer_protocol.dart`

定义了完整的传输协议框架：
- **TransferProtocol**: 协议帧类型常量
- **TransferPlan**: 传输计划数据结构
- **TransferStats**: 传输统计信息
- **TransferError**: 错误信息定义

### 2. 改进的传输流程

#### 原始流程
```
TCP连接 → FILE_TRANSFER_REQUEST → FILE_META → CHUNK → FILE_END
```

#### 改进后的流程
```
TCP连接 
  ↓
FILE_TRANSFER_REQUEST (请求传输)
  ↓
FILE_TRANSFER_ACCEPTED (接受请求)
  ↓
TRANSFER_PLAN (协商传输计划) ← 新增
  ↓
TRANSFER_PLAN_ACK (确认计划) ← 新增
  ↓
FILE_META (发送文件元数据)
  ↓
FILE_META_ACK (确认元数据)
  ↓
CHUNK (逐个发送分片)
  ↓
CHUNK_ACK (确认分片)
  ↓
FILE_END (文件结束)
  ↓
FILE_END_ACK (最终确认)
```

### 3. TRANSFER_PLAN协议设计

#### 发送端计算传输计划
```dart
final totalChunks = (total + chunkSize - 1) ~/ chunkSize;
final lastChunkSize = total - (totalChunks - 1) * chunkSize;

final transferPlan = TransferPlan(
  fileName: name,
  fileSize: total,
  chunkSize: chunkSize,
  totalChunks: totalChunks,
  lastChunkSize: lastChunkSize,
  timeoutSeconds: 30,
);
```

#### 传输计划帧格式
```json
{
  "type": "TRANSFER_PLAN",
  "fileName": "file.apk",
  "fileSize": 31284684,
  "chunkSize": 1048576,
  "totalChunks": 30,
  "lastChunkSize": 284684,
  "timeoutSeconds": 30
}
```

#### 接收端验证传输计划
```dart
// 验证计划有效性
if (!transferPlan.isValid()) {
  // 拒绝传输
  return;
}

// 保存计划信息
conn.transferPlan = transferPlan;

// 发送ACK确认
conn.send({'type': 'ACK', 'for': 'TRANSFER_PLAN'});
```

### 4. 改进的分片处理

#### 发送端
```dart
// 发送分片控制帧（包含分片索引）
p.send({
  'type': 'CHUNK',
  'index': chunkIndex,
  'size': read,
});

// 发送二进制数据
s.add(buffer.sublist(0, read));
await s.flush();

// 等待ACK确认
await p.waitForAck(forType: 'CHUNK', timeout: Duration(seconds: 10));
```

#### 接收端
```dart
// 验证分片索引和大小
if (conn.transferPlan != null && chunkIndex >= 0) {
  final expectedChunkSize = conn.transferPlan!.getChunkSizeAt(chunkIndex);
  if (chunkSize != expectedChunkSize) {
    print('⚠️ 分片大小不匹配');
  }
}

// 接收二进制数据
final data = await conn.readBinaryData(chunkSize);

// 写入文件并刷新
conn.currentFileStream!.add(data);
await conn.currentFileStream!.flush();

// 更新统计信息
conn.receivedBytes += data.length;
conn.receivedChunks++;

// 发送ACK确认
conn.send({'type': 'ACK', 'for': 'CHUNK'});
```

### 5. 改进的二进制数据处理

#### 接收端缓冲区管理
```dart
// 混合处理控制帧和二进制数据
void _onData(List<int> data) {
  // 将数据添加到二进制缓冲区
  _binaryBuffer.addAll(data);
  
  // 优先处理等待中的二进制数据请求
  if (_waitingForBinaryData) {
    _checkBinaryBuffer();
  } else {
    // 处理控制帧
    _processControlFrames();
  }
}

// 检查缓冲区是否满足二进制数据需求
void _checkBinaryBuffer() {
  if (_binaryBuffer.length >= _requiredBinarySize!) {
    final result = _binaryBuffer.sublist(0, _requiredBinarySize!);
    _binaryBuffer.removeRange(0, _requiredBinarySize!);
    _binaryDataCompleter!.complete(result);
  }
}
```

## 关键改进点

### 1. 明确的期望
- 接收端知道要接收多少个分片
- 每个分片的确切大小
- 总文件大小

### 2. 更好的同步机制
- 双方都清楚传输计划
- 避免等待不确定的数据量
- 每个分片都有明确的索引

### 3. 更容易的验证
- 可以验证接收到的分片数是否正确
- 可以验证每个分片的大小
- 可以计算传输进度

### 4. 更好的错误处理
- 如果某个分片丢失，可以重新传输
- 清晰的错误消息
- 完整的日志记录

### 5. 进度跟踪
- 可以准确计算传输进度
- 可以估算剩余时间
- 可以计算传输速度
